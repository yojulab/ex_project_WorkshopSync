# WorkshopSync 도메인 전문 용어 사전 및 10대 비즈니스 골든 룰
## (WorkshopSync Terminology & 10 Golden Business Rules)

- **참조 원본**: `docs/initial_PRD.md` (워크샵 참석자 전용 앱 작업지시서 v1.0)
- **적용 대상**: WorkshopSync 플랫폼을 설계하고 검증하는 모든 하네스 에이전트 및 개발자
- **목적**: 워크샵 기획사, 기업 클라이언트, 일반 참석자, 운영자 간의 혼선을 방지하고, 토스풍 모바일 UX와 게이미피케이션(투표/순위/시상) 규칙의 무결성을 시스템 수준에서 보장함.

## 1. 워크샵 핵심 도메인 용어 체계 (Glossary)

| 구분 | 표준 도메인 용어 | 영문 / 코드 식별자 | 정의 및 핵심 비즈니스 규칙 (Rule Point) |
| :--- | :--- | :--- | :--- |
| **참석/인증** | **워크샵 코드** | `joinCode` | 워크샵 개설 시 발급되는 고유 영문/숫자 코드. URL 딥링크 또는 현장 배포용. |
| **참석/인증** | **사전 등록 명단** | `Participant Directory` | 관리자가 CSV로 일괄 등록한 명단(이름, 전화번호, 소속사, 조, 유형). 일치 시에만 입장 허용. |
| **참석/인증** | **체크인 (Check-in)** | `checkin` / `checkedInAt` | 현장 QR 스캔 또는 코드로 출석 확인. 중복 체크인 시 최초 시각을 유지하며 멱등하게 성공. |
| **참석자 유형** | **클라이언트 / 일반 소비자** | `client` / `consumer` | 워크샵을 의뢰한 기업 임직원(`client`)과 참석한 소비자(`consumer`)를 구분하여 필요 시 통계 분리. |
| **일정/조** | **아젠다 타임라인** | `Agenda Timeline` | 워크샵 시간별 세션 진행표. 현재 진행 중인 세션은 모바일 앱 상단에 실시간 하이라이트. |
| **일정/조** | **조 / 팀 (Team)** | `Team` / `teamId` | 워크샵 협업 단위. 조 이름, 고유 테마 컬러, 조원 목록으로 구성. 수동 또는 자동 배정. |
| **미션** | **미션 스코프 (Scope)** | `scope: team` \| `individual` | 조별 공동 과제(`team`)와 개인별 과제(`individual`)로 구분. |
| **제출물** | **작업물 (Submission)** | `Submission` | 미션에 맞춰 제출한 이미지, 문서, 영상, 링크, 코멘트. 조별 미션은 조당 1건 최종물 관리. |
| **제출물** | **임시저장 / 제출완료** | `draft` / `submitted` | 작성 중인 상태(`draft`)와 최종 제출 상태(`submitted`). 마감시간 전까지 수정 가능. |
| **공유** | **같이보기 갤러리** | `Gallery Viewer` | 전체 조와 개인의 제출물을 카드 그리드 및 가로 스와이프 뷰어로 함께 열람하는 공간. |
| **공유** | **피드백 메모** | `Feedback Memo` | 카카오톡 채팅형의 가벼운 1줄 응원/피드백 댓글 기능. 작성자 본인만 수정/삭제 가능. |
| **투표** | **선호도 투표** | `Preference Voting` | 조별 결과물에 대해 참석자들이 1인 1표(기본)를 행사하는 게이미피케이션 투표. |
| **투표** | **자기 조 투표 금지** | `No Self-Voting Rule` | 공정성을 위해 자신이 소속된 조의 제출물에는 투표 불가 (UI 비활성화 및 서버 400 차단). |
| **투표** | **블라인드 득표** | `Blind Tally` | 투표 진행 중에는 실시간 득표수를 참석자에게 일절 비공개 처리하여 편향 방지. |
| **시상** | **순위 공개** | `ranking/publish` | 관리자가 투표 종료 후 순위 공개 버튼을 눌렀을 때만 전체 참석자에게 순위 화면 오픈. |
| **시상** | **우승팀 / 최고 작업자** | `winningTeam` / `topWorker` | 최다 득표 1위 조(`winningTeam`) 및 탁월한 개인 기여도를 보인 최고 작업자(`topWorker`). |
| **시상** | **컨페티 축하 연출** | `Confetti Celebration` | 우승자 확정 시 전체 참석자 스마트폰 화면 가득 꽃가루가 터지는 축하 인터랙션(S-12). |
| **실시간** | **SSE 실시간 스트림** | `Server-Sent Events` | 대시보드 진행률, 긴급 공지 토스트, 투표 상태 전이, 수상 알림을 1초 내 푸시. |

## 2. WorkshopSync 현장 압축 "10대 비즈니스 골든 룰" (Golden Rules)

1. **[자기 조 투표 금지 원칙 (No Self-Voting)]**:
   조별 미션 투표 시 자신의 조(`participant.teamId`)에는 절대 투표할 수 없다. 모바일 UI에서 시각적으로 비활성화하고, 서버 API에서도 엄격히 검증하여 반려한다.
2. **[실시간 득표수 비공개 원칙 (Blind Voting)]**:
   투표가 진행되는 동안에는 참석자에게 실시간 득표수나 득표율을 절대 노출하지 않는다. 관리자가 명시적으로 '순위 공개'를 승인한 후에만 순위표(S-11)가 개방된다.
3. **[마감 시한 엄격 차단 원칙 (Strict Due Time)]**:
   미션 마감 시각(`dueAt`)이 경과하면 신규 작업물 업로드 및 수정이 즉시 차단되며, 상태가 `마감(미제출)` 또는 `제출완료(수정불가)`로 잠긴다.
4. **[체크인 최초 시각 보존 원칙 (Idempotent Check-in)]**:
   참석자가 네트워크 불안 등으로 QR 스캔이나 체크인 요청을 여러 번 시도하더라도, 데이터베이스에는 최초 체크인 시각(`checkedInAt`)을 영구 보존하며 멱등성을 보장한다.
5. **[조별 제출물 단일화 및 버전 이력 원칙 (Team Submission Singularity)]**:
   조별 미션은 조원 중 누구나 제출·수정할 수 있으나 조당 최종 제출물은 항상 1건으로 유지되며, 이전 작업물이 유실되지 않도록 버전 번호(`version`)를 증가시켜 이력을 관리한다.
6. **[하단 고정 풀폭 CTA 원칙 (Toss UX Spirit)]**:
   모든 참석자 모바일 화면(S-01~S-13)의 핵심 액션(입장하기, 체크인, 제출하기, 투표하기 등)은 엄지손가락이 닿기 쉬운 **하단 고정 풀폭(Full-width) 라운드 버튼(12~16px)**으로 통일한다.
7. **[카카오톡식 5대 하단 탭 및 알림 중심 네비게이션]**:
   모바일 앱은 `[홈]` · `[미션]` · `[결과물]` · `[투표/순위]` · `[알림]` 5대 탭을 상시 유지하며, 알림 발생 시 탭 뱃지 및 인앱 플로팅 토스트로 즉각적인 피드백을 제공한다.
8. **[SSE 실시간 푸시 & 컨페티 우승 축하 파이프라인]**:
   관리자가 우승팀/최고 작업자를 선정하여 확정하는 즉시, 새로고침 없이 모든 참석자의 스마트폰 화면에 화려한 컨페티(꽃가루) 파티클 애니메이션과 축하 알림이 동시 발동되어야 한다.
9. **[포트 30015부터 시작하는 3대 타겟 독립 서빙 원칙]**:
   - `30015`: REST API 서버 (`apps/api`)
   - `30016`: 참석자 전용 앱 (`apps/mobile` PWA)
   - `30017`: 관리자 웹 (`apps/admin`)
   모든 서비스는 독립 빌드/기동되며 데이터 교환은 오직 REST API (`/api/v1`) 및 SSE 스트림으로만 수행한다.
10. **[의뢰자 소통용 UI 일련번호 및 Alt+I 4대 정보 원클릭 복사]**:
    모든 화면과 상호작용 요소에 고유 일련번호(`[S01-SEC01-BTN01]`)를 부여하고, `Alt + I` 단축키로 토글되는 뱃지 클릭 시 **4대 정보(일련번호, 페이지명, URI, 항목명)**가 클립보드에 즉시 복사되어 오차 없는 피드백을 지원한다.
